# 阶段流程与交接

## 状态转换

`S0_SCOPE → S1_SOURCE_CHECK → S2_DATA → S3_ANALYSIS → S4_ACTION → S5_REPORT → S6_QA_DELIVERY`

状态更新写入项目工作目录的 `progress.json`，至少包括当前状态、完成时间、阶段产物路径、覆盖状态、错误和待办。只有阶段验收通过才推进；失败后保留错误状态并说明重试条件。

## S0_SCOPE｜研究范围

先确认：研究对象、决策人、目标市场、时间范围、竞品、核心问题、所需平台/数据域和最终格式。范围记录应区分已确认信息、待确认项和分析假设。

**交付：** `00_scope.md`、`scope.json`。  
**验收：** 读者能看出研究要支持什么决策，以及明确不研究什么。

## S1_SOURCE_CHECK｜数据覆盖

连接 ClaudeBaby MCP，查看与本项目相关的工具、平台、站点、字段、授权和可用时间窗。对目标数据先做小范围探测，记录成功、无命中、权限不足、上游错误和字段缺失。不要将“工具存在”写成“数据已获取”。

**交付：** `01_source_coverage.xlsx`，包含查询草案、覆盖矩阵与状态。  
**验收：** 每个研究维度都标明可取、部分可取或不可取，并列出影响。

## S2_DATA｜采集与整理

只通过 ClaudeBaby MCP 取外部数据。保留原始响应或其可复核归档，并整理记录 ID、平台、站点/市场、查询词、采集时间、内容时间、字段、来源链接、去重规则、分页状态和错误状态。必要时使用脱敏 JSON/CSV 附件。

**交付：** `02_research_data.xlsx` 及原始响应索引。  
**验收：** 每一组数字都能回到样本、口径和采集窗口；错误不等于零值。

## S3_ANALYSIS｜分析与判断

按研究问题比较趋势、市场、关键词、商品、竞品和反馈。区分直接观测、计算结果、分析解释和待验证假设；同时记录反例、分母、偏差和数据缺口。

**交付：** `03_findings.xlsx` 与结论摘要。  
**验收：** 每项关键发现都有证据定位、口径、限制和业务含义。

## S4_ACTION｜部门行动

逐条将发现转成行动：任务、证据依据、目标团队、负责人角色、优先级、时间、KPI、依赖和复盘节点。缺少证据的建议标为实验假设，并给出验证方式。

**交付：** `04_department_playbooks.xlsx`，以及市场/品牌/内容/SEO/GEO/电商等适用部门的独立行动手册。  
**验收：** 团队成员拿到后知道做什么、衡量什么、何时复盘。

## S5_REPORT｜综合报告

按“结论—证据—影响—行动”组织内容。执行摘要回答管理者最关心的决定；正文说明证据与限制；附录给出数据口径、来源和计算方式。图表必须与工作簿同源。

**交付：** `05_final_report.html`（或用户指定格式）和完整工作簿。  
**验收：** 报告与 Excel 数字一致，不隐藏覆盖缺口。

## S6_QA_DELIVERY｜质检交付

检查工作簿与报告能否打开；核对数字、公式、单位、分母、时间范围、来源链接和图表；检查文件是否误含密钥、账号信息或客户私有数据。记录未通过项和后续复测建议。

**交付：** `06_QA_and_delivery.md`、最终文件清单与可访问路径。  
**验收：** 每个质检项为通过、未通过或未执行，不把未验证说成通过。
